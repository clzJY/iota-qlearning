THE PROBLEM

Reach the target.
Learn which move to take.

The robot can move between rooms through doorways. At each step, it knows its current room and the moves available there. It needs to learn which move will help it reach the target. I model each room as a state and each move into a neighboring room as an action.

For my first experiment, the robot starts in C and the target is F. I read these positions from the robot and dock in the assignment’s Figure 1. The second experiment follows the assignment’s stated change: start in A and make C the target.

For example, from C the robot can enter B or D. In D, it can move to B, C, or E. Which of those choices brings it closer to the target? The robot will learn action values from experience rather than being given the answer.

I will explain the learning rule, examine C → F, repeat it for A → C, and compare the results. Additional experiments come afterwards.

The assignment provides a schematic room drawing rather than a transition matrix. The B–C doorway is included, as clarified from Figure 1. The room graph and both diagrams use the same seven connections. Once a room is the target, the episode ends on entry; the robot does not take further actions there.

PART 01

Motivation and method

I give the robot a reward of 1 when it reaches the target and 0 for every other move. Q-learning stores an estimate for every allowed room-and-move pair. This estimate, called a Q-value, describes how much future reward the robot expects from that move if it then acts optimally.

A larger Q-value makes a move more attractive. Future rewards are discounted, so reaching the target sooner is worth more than taking a long detour. These values are discounted reward estimates, not probabilities.

After a move, the robot compares its old estimate with a new target: the reward it just received, plus the discounted best estimate in the next room. It moves the old estimate partway towards that target. On reaching the goal, there is no next action, so the target is simply the reward of 1.

Q-LEARNING UPDATE

new estimate = old estimate
+ α × (target − old estimate)

For an ordinary move:
target = reward + γ × best next Q

For a move into the goal:
target = reward

α, the learning rate, controls how much an estimate changes.
γ, the discount factor, reduces the value of delayed rewards.

To choose a move, the robot usually follows its highest current Q-value. Sometimes it tries a random legal move instead. This is ε-greedy exploration: ε is the probability of making that random choice. Without trying alternatives, the robot could miss useful routes.

The update always uses the best legal next Q-value, even when exploration makes the robot choose a different action. That is why Q-learning is called an off-policy method [1]. In symbols, the ordinary update is Q(s,a) ← Q(s,a) + α[r + γ maxb ∈ A(s′) Q(s′,b) − Q(s,a)]. Terminal moves omit the future-value term.

ONE REWARD, LEARNED BACKWARDS

How does reaching F teach the earlier move from C?

Start with every Q-value at zero and imagine the robot takes C → B → F. The first C → B move changes nothing yet: it earns zero and B has no learned value. Reaching F then gives a reward of 1.

  1. Reaching the goal: B → F

    The target is the terminal reward, 1. With a learning rate of 0.1, Q(B,F) moves one tenth of the way from 0 towards 1.

    0 + 0.1 × (1 − 0) = 0.100
  2. On the next attempt: C → B

    Now B’s best learned value is 0.1. C → B still earns zero immediately, but its target includes that future reward estimate, discounted by 0.9.

    0 + 0.1 × (0 + 0.9 × 0.1 − 0) = 0.009

The point: a move can become valuable even when it earns no reward itself. Repeated visits let the goal reward influence earlier decisions. The small 0.009 estimate is a first update; it is not the final value of the move.

This is a hand-calculated teaching sequence using the experiment’s fixed α = 0.1 and γ = 0.9. It is not a claim about the order of actions in a particular saved run.

PART 02

Environment and experimental setup

I train the two required configurations separately. Every run starts with a fresh Q-table: all allowed moves initially have value zero. Nothing learned in C → F is carried over into A → C.

One episode is one attempt to reach the goal. It starts in the configured room and ends when the target is reached. A 100-move cap stops an attempt if it runs too long. That cap is a sampling limit, not a new goal, so its final nonterminal update still includes a future value.

Random exploration can change the learning path. I therefore repeat each experiment with 20 random seeds. The tables below show the preselected run with seed 0, while the plots also show variation across all 20 runs.

The shared training settings. I keep these fixed so that the two experiments use the same learning procedure.

Implementation choices

Only adjacent-room actions are available; blocked moves are masked rather than assigned numeric Q-values. The goal has no outgoing actions and no self-loop. Greedy ties during training are broken uniformly at random. Evaluation selects the alphabetically first action among exact ties and uses none of the training random-number stream.

All seeds are 0–19, using NumPy default_rng with PCG64. The recorded training environment is Python 3.13.12 and NumPy 2.5.3. The same seed list is reused across configurations, but different trajectories consume random draws differently. I train for the full budget rather than stopping when a plot appears flat.

PART 03

Results for both configurations

I need to answer two questions: which moves does the robot learn to choose, and do its value estimates settle down? The Q-tables answer the first question. The learning plots help answer the second.

How to read a Q-table. A row is the room the robot is in. A column is the room it could move into. Read across one row and choose a largest value. A dash means that move is unavailable; it is not a zero-valued choice. The target row is all dashes because the robot stops there.

How to read the plots. The first panel follows the robot’s best estimate for its first move. The second checks the largest error anywhere in the table. I can calculate exact values for this small deterministic map, so a falling error line means that the learned table is getting closer to the correct one. These exact values are used only for checking, never to teach the learner its answer.

What counts as convergence here? I require the largest absolute Q-value error over every allowed move to stay below 0.001 for at least 100 consecutive episodes through the end of the run. This is a finite-run accuracy check, not a proof of the general Q-learning convergence theorem. All plots use the median across 20 seeds; shaded bands span the 10th–90th percentiles and show variation between runs, not confidence intervals.
{{REQUIRED_RESULTS}}
Reference values and convergence criterion

The exact reference is Q*(s,a) = 0.9d(a,g), where d is the shortest distance from the room reached by action a to goal g. An action entering the goal has d = 0, so its exact value is 1. Starting two moves from F gives a first-action value of 0.9; starting three moves from C gives 0.9² = 0.81. The immediate reward is discounted by the zeroth power, so a route with n moves has first-action value 0.9n−1.

I calculate distances with breadth-first search and check the reference independently with value iteration. The full-table error after episode e is Ee = max(s,a) valid |Qe(s,a) − Q*(s,a)|. The error panel uses a logarithmic vertical axis: equal vertical steps represent factors of ten. Values below 10−12 are drawn at that floor; the CSVs retain their actual precision.

The accuracy episode is the beginning of the final below-threshold sequence, provided that sequence lasts at least 100 episodes. This is checked after the fixed run has finished. It is not an early-stopping rule.

PART 04

Comparison and critical analysis

Moving the goal changes what a good move is.

With F as the goal, a robot in D should move towards B or E. With C as the goal, it should move directly to C instead. The reward and stopping point have changed, so the robot needs a different Q-table. F now has outgoing actions, while C becomes the terminal row.

With the B–C doorway, C → B → F takes two moves, while A → E → D → C takes three. The exact best first-action values are therefore 0.90 for C → F and 0.81 for A → C. The original route reaches its reward sooner, so it has less discounting.

Exploration and value accuracy

I repeat C → F with ε = 0, keeping every other main setting fixed. The robot no longer deliberately tries random alternatives, although exact ties are still broken randomly. Once a positive-valued route emerges, other moves may receive little attention.

Here I distinguish accuracy from change. Accuracy asks whether the values are right. Episode change asks how much the table changed during one attempt. An incorrect value can stay almost unchanged if the robot rarely revisits it.

{{ABLATION_ANALYSIS}}

Compare the two panels below. In the first, a high orange line means large errors remain without forced exploration. In the second, a low orange line means the table is barely changing. Seeing both at once explains how a flat learning curve can give a misleading impression of convergence.

The lesson is that a successful route, a stable table, and an accurate table are different outcomes. I therefore also retain action visit counts and the Bellman residual, which checks whether the table agrees with a one-step optimal backup of the known model. PART 05

Takeaways and references

Q-learning learns useful action values by revising estimates after sampled moves. In both required experiments, the learned greedy policy reaches the target by a shortest route, and the complete table passes my declared accuracy check across all 20 seeds.

Changing from C → F to A → C changes which actions deserve high values and which room ends an episode. The corrected map gives a two-move original route and a three-move modified route, with different policies and first-action values. The plots show how the estimates develop; repeated runs show how much the learning process varies with randomness.

These conclusions apply to this small deterministic room graph and the stated settings. The finite runs with constant α = 0.1 do not prove the classical asymptotic convergence result, which also requires repeated sampling and suitable step-size conditions [2]. Larger or noisy environments, other parameters, and other room-graph interpretations could behave differently.
