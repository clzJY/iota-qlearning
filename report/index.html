LEARNING TO NAVIGATE

How do robots
find the goal?

A robot needs to reach a target room. How can it learn which doorway to choose?

We use Q-learning to learn from the moves it tries. Then we change the start and target to see what the robot learns differently.

Start with the problem ↓

THE PROBLEM

Reach the target.
Learn which move to take.

The robot can move between rooms through doorways. At each step, it knows its current room and the moves available there. It needs to learn which move will help it reach the target. We model each room as a state and each move into a neighboring room as an action.

For our first experiment, the robot starts in C and the target is F. We read these positions from the robot and dock in the assignment’s Figure 1. The second experiment follows the assignment’s stated change: start in A and make C the target.

For example, from C the robot must first enter D. In D, it can move to B, C, or E. Which of those choices brings it closer to the target? The robot will learn action values from experience rather than being given the answer.

We will explain the learning rule, examine C → F, repeat it for A → C, and compare the results. Additional experiments come afterwards.

The assignment provides a schematic room drawing rather than a transition matrix. These connections are our explicit room-graph interpretation. Once a room is the target, the episode ends on entry; the robot does not take further actions there.

THE METHOD

Learn from the moves
the robot tries.

We give the robot a reward of 1 when it reaches the target and 0 for every other move. Q-learning stores an estimate for every allowed room-and-move pair. This estimate, called a Q-value, describes how much future reward the robot expects from that move if it then acts optimally.

A larger Q-value makes a move more attractive. Future rewards are discounted, so reaching the target sooner is worth more than taking a long detour. These values are discounted reward estimates, not probabilities.

After a move, the robot compares its old estimate with a new target: the reward it just received, plus the discounted best estimate in the next room. It moves the old estimate partway towards that target. On reaching the goal, there is no next action, so the target is simply the reward of 1.

Q-LEARNING UPDATE

new estimate = old estimate
+ α × (target − old estimate)

For an ordinary move:
target = reward + γ × best next Q

For a move into the goal:
target = reward

α, the learning rate, controls how much an estimate changes.
γ, the discount factor, reduces the value of delayed rewards.

To choose a move, the robot usually follows its highest current Q-value. Sometimes it tries a random legal move instead. This is ε-greedy exploration: ε is the probability of making that random choice. Without trying alternatives, the robot could miss useful routes.

The update always uses the best legal next Q-value, even when exploration makes the robot choose a different action. That is why Q-learning is called an off-policy method [1]. In symbols, the ordinary update is Q(s,a) ← Q(s,a) + α[r + γ maxb ∈ A(s′) Q(s′,b) − Q(s,a)]. Terminal moves omit the future-value term.

WORKED EXAMPLE

What changes after one move?

Suppose the current estimate is 0.20 and the best estimate in the next room is 0.60. With γ = 0.90, the target is 0.54. A learning rate of 0.10 moves the estimate one tenth of the way from 0.20 to 0.54, giving 0.234.

If the move reaches the goal instead, the target is 1 and the new estimate is 0.280. These are illustrative numbers, not a recorded training episode.

BEFORE WE LOOK AT THE RESULTS

Train the same way.
Change the start and goal.

We train the two required configurations separately. Every run starts with a fresh Q-table: all allowed moves initially have value zero. Nothing learned in C → F is carried over into A → C.

One episode is one attempt to reach the goal. It starts in the configured room and ends when the target is reached. A 100-move cap stops an attempt if it runs too long. That cap is a sampling limit, not a new goal, so its final nonterminal update still includes a future value.

Random exploration can change the learning path. We therefore repeat each experiment with 20 random seeds. The tables below show the preselected run with seed 0, while the plots also show variation across all 20 runs.

Exact implementation choices

Only adjacent-room actions are available; blocked moves are masked rather than assigned numeric Q-values. The goal has no outgoing actions and no self-loop. Greedy ties during training are broken uniformly at random. Evaluation selects the alphabetically first action among exact ties and uses none of the training random-number stream.

All seeds are 0–19, using NumPy default_rng with PCG64. The recorded training environment is Python 3.13.12 and NumPy 2.5.3. The same seed list is reused across configurations, but different trajectories consume random draws differently. We train for the full budget rather than stopping when a plot appears flat.

THE REQUIRED EXPERIMENTS

What did the robot learn?

We need to answer two questions: which moves does the robot learn to choose, and do its value estimates settle down? The Q-tables answer the first question. The learning plots help answer the second.

How to read a Q-table. A row is the room the robot is in. A column is the room it could move into. Read across one row and choose a largest value. A dash means that move is unavailable; it is not a zero-valued choice. The target row is all dashes because the robot stops there.

How to read the plots. The first panel follows the robot’s best estimate for its first move. The second checks the largest error anywhere in the table. We can calculate exact values for this small deterministic map, so a falling error line means that the learned table is getting closer to the correct one. These exact values are used only for checking, never to teach the learner its answer.

What counts as convergence here? We require the largest absolute Q-value error over every allowed move to stay below 0.001 for at least 100 consecutive episodes through the end of the run. This is a finite-run accuracy check, not a proof of the general Q-learning convergence theorem. All plots use the median across 20 seeds; shaded bands span the 10th–90th percentiles and show variation between runs, not confidence intervals.

How the exact values and error are calculated

The exact reference is Q*(s,a) = 0.9d(a,g), where d is the shortest distance from the room reached by action a to goal g. An action entering the goal has d = 0, so its exact value is 1. Starting three moves from the goal gives a first-action value of 0.9² = 0.81: the reward arrives on the third transition.

We calculate distances with breadth-first search and check the reference independently with value iteration. The full-table error after episode e is Ee = max(s,a) valid |Qe(s,a) − Q*(s,a)|. The error panel uses a logarithmic vertical axis: equal vertical steps represent factors of ten. Values below 10−12 are drawn at that floor; the CSVs retain their actual precision.

The accuracy episode is the beginning of the final below-threshold sequence, provided that sequence lasts at least 100 episodes. This is checked after the fixed run has finished. It is not an early-stopping rule.

COMPARING THE TWO REQUIRED CASES

Moving the goal changes what a good move is.

With F as the goal, a robot in D should move towards B or E. With C as the goal, it should move directly to C instead. The reward and stopping point have changed, so the robot needs a different Q-table. F now has outgoing actions, while C becomes the terminal row.

Both starting positions happen to be three moves from their respective goals. That is why their best first-action values approach the same number, 0.81. Equal starting values do not mean equal policies: the destinations, preferred moves, and other table entries differ.

The whole-table accuracy check was reached at a median episode of 1,119 for C → F and 767.5 for A → C. Under these settings, the second case learned the full table sooner on that measure. The shaded bands show randomness across seeds; these medians are not guaranteed learning times.

Changing only a start would change the experiences collected during training, but not the exact optimal values for a fixed goal. Here we changed both the start and goal together, as required. Their combined effect cannot tell us which change caused the learning-speed difference; the further experiments below investigate that distinction.

GOING FURTHER

Two questions
raised by the results.

The two required experiments above complete the assignment’s core comparison. We then add two investigations: whether a shorter route makes the whole table easier to learn, and whether the robot can find a good route without learning every value accurately.

Does a shorter route make the whole table faster to learn?

To separate start and target effects, we add A → F, B → F, and B → C. Together with A → C, these compare starts A/B with targets F/C while holding the other setting fixed. We use B rather than C as the second start because C → C would finish before the robot takes a move.

Read the table as a comparison of learning speed. “Accuracy episode” tells us when the entire table passes the 0.001 check. The range shows variation between seeds. “Transitions” counts actual moves, since equal episode budgets need not involve equal numbers of moves. The visit count shows how much attention the least-sampled action received.

A shorter route can leave a slower table.

Holding the goal at F, changing the start from C to A reduces the shortest route from three steps to two. Yet median full-table accuracy moves from 1,119 to 4,769 episodes. The descriptive seed-matched difference is 3,573.5 [2,061.3, 4,774.1] episodes (median [P10, P90]). Starting nearer the goal gives fewer opportunities to sample distant branches in each episode. This interpretation is consistent with the saved visit counts; it is not a universal law about start distance.

The target changes the learning problem.

Holding the start at B, switching target F to C increases the shortest route from one step to two, yet median full-table accuracy improves from 6,286.5 to 1,103.5 episodes. Goal F terminates on entering a well-connected room, while reaching leaf C requires passing through D. Coverage and termination structure matter beyond path length. Final reference tables for the same goal agree regardless of start, while changing the goal changes valid terminal actions and values.

The results show why shortest-path length alone is not enough to predict whole-table learning speed: a short successful episode may rarely reach distant branches. These are descriptive comparisons in one small graph, with no significance claim or claim of a universal relationship. Seed-level data are in summary.csv.

Can the robot find a good route while some values remain wrong?

We repeat C → F with ε = 0, keeping every other main setting fixed. The robot no longer deliberately tries random alternatives, although exact ties are still broken randomly. Once a positive-valued route emerges, other moves may receive little attention.

Here we distinguish accuracy from change. Accuracy asks whether the values are right. Episode change asks how much the table changed during one attempt. An incorrect value can stay almost unchanged if the robot rarely revisits it.

In these saved runs, 20/20 final greedy policies take a shortest route. Nevertheless, final full-table errors range from 0.900 to 1.000, and 0–7 valid action pairs per run were never visited. No run meets the full-table tolerance. Episode changes remain below 0.001 from a median episode of 77 onwards for at least 100 episodes through the run end.

Compare the two panels below. In the first, a high orange line means large errors remain without forced exploration. In the second, a low orange line means the table is barely changing. Seeing both at once explains how a flat learning curve can give a misleading impression of convergence.

The lesson is that a successful route, a stable table, and an accurate table are different outcomes. We therefore also retain action visit counts and the Bellman residual, which checks whether the table agrees with a one-step optimal backup of the known model. In the two required cases, the largest final residual across all 40 runs is 5.55e-16, and every valid pair has at least 2,116 visits.

Why we increased exploration and the training budget after a pilot

A retained pilot used ε = 0.2 and 3,000 episodes. All 20 runs in each required case found a shortest route, but the worst full-table errors were 0.491 (C → F) and 0.093 (A → C). Some actions had received too few updates. We increased ε to 0.5 and the budget to 20,000 episodes to improve coverage.

Both settings changed, so this pilot is a reason for the final protocol, not a controlled estimate of either setting’s individual effect. All pilot outputs and their source provenance remain in experiments/pilot_3000/.

WHAT WE LEARNED

The target changes.
The values must change with it.

Q-learning learns useful action values by revising estimates after sampled moves. In both required experiments, the learned greedy policy reaches the target by a shortest route, and the complete table passes our declared accuracy check across all 20 seeds.

Changing from C → F to A → C changes which actions deserve high values and which room ends an episode. Both optimal routes have three moves, but their policies and tables differ. The plots show how the estimates develop; repeated runs show how much the learning process varies with randomness.

These conclusions apply to this small deterministic room graph and the stated settings. Our finite runs with constant α = 0.1 do not prove the classical asymptotic convergence result, which also requires repeated sampling and suitable step-size conditions [2]. Larger or noisy environments, other parameters, and other room-graph interpretations could behave differently.
